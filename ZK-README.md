# ZK-ML Cognition Proof — Implementation Guide

## What was built

| File | Purpose |
|------|---------|
| `circuits/relu.circom` | Core circuit: ReLU activations + Poseidon weight commitment |
| `contracts/Groth16Verifier.sol` | On-chain pairing verifier (placeholder until `zk-setup.ts` runs) |
| `contracts/CognitionVerifier.sol` | Wraps verifier with commitment check + replay protection |
| `scripts/zk-setup.ts` | Trusted setup: compiles circuit → generates real `Groth16Verifier.sol` |
| `scripts/zk-prove.ts` | Agent proof generation: runs before every `validateTransaction()` |
| `scripts/deploy-nexus.ts` | Updated deploy: wires real verifier, removes MockCognitionVerifier |
| `test/ZKCognition.test.ts` | Test suite: 9 tests covering all error paths |

## Step-by-step: Zero to working ZK proof

### 1. Install dependencies

```bash
# ZK toolchain
npm install snarkjs circomlibjs
npm install -g circom          # or: brew install circom

# Verify circom is installed
circom --version               # should print circom compiler 2.x.x
```

### 2. Run trusted setup (one-time per circuit)

```bash
npx ts-node scripts/zk-setup.ts
```

This will:
- Compile `circuits/relu.circom` → `.r1cs` + `.wasm`
- Download the Hermez Powers of Tau file (~55MB, public ceremony)
- Run Phase 2 setup → `circuits/build/relu_final.zkey`
- Export `circuits/build/verification_key.json`
- **Overwrite** `contracts/Groth16Verifier.sol` with real pairing constants

> ⚠️ If agent logic ever changes, re-run this step.  
> For production: use PlonK (universal setup) to avoid re-running ceremony on logic changes.

### 3. Run tests

```bash
npx hardhat test test/ZKCognition.test.ts
```

### 4. Deploy to Arc Testnet

```bash
npx hardhat run scripts/deploy-nexus.ts --network arcTestnet
```

Saves addresses to `deployment/unknown-1234.json`.

### 5. Register an agent (with model commitment)

When an agent mints its NFT in `AgentRegistry`, immediately call:

```typescript
// In your agent registration flow:
import { buildPoseidon } from "circomlibjs";

const poseidon  = await buildPoseidon();
const weights   = [1n, 2n, 3n, 4n, 5n, 6n, 7n, 8n]; // your model weights
const hash      = poseidon(weights);
const commitment = poseidon.F.toObject(hash);

await cognitionVerifier.registerCommitment(agentAddress, commitment);
```

### 6. Generate a proof (agent side, before each transaction)

```bash
# Using demo values
npx ts-node scripts/zk-prove.ts

# Using real inference output
echo '{"pre":[42,0,7,100,0,55,3,88],"weights":[1,2,3,4,5,6,7,8]}' > input.json
npx ts-node scripts/zk-prove.ts --input=input.json
```

Outputs `circuits/proofs/tx_payload_<timestamp>.json` containing:
- `proofData` — bytes to pass to `validateTransaction()`
- `publicInputs` — uint256[] to pass alongside

### 7. Submit the transaction

```typescript
const payload = JSON.parse(fs.readFileSync("circuits/proofs/tx_payload_xxx.json"));

await agentGuardian.validateTransaction(
    agentAddress,
    recipientAddress,
    amount,
    payload.proofData,
    payload.publicInputs
);
```

## Architecture diagram

```
Agent (off-chain)
    │
    ├── runs model inference
    ├── computes post = ReLU(pre)
    ├── zk-prove.ts → generates Groth16 proof
    │
    ▼
AgentGuardian.validateTransaction(agent, recipient, amount, proof, publicInputs)
    │
    ├── calls CognitionVerifier.verify(agent, proof, publicInputs)
    │       │
    │       ├── checks commitment[agent] == publicInputs[8]  (model integrity)
    │       ├── checks !usedProofs[hash(proof)]              (replay protection)
    │       └── calls Groth16Verifier.verify(proof, publicInputs)
    │                   │
    │                   └── bn128 pairing check (EVM precompile 0x08)
    │
    └── if all pass → approves transaction
```

## The 3 PhD-level concerns — addressed

### 1. Witness generation bottleneck
The `.wasm` file generated by circom runs in Node.js via snarkjs `fullProve()`. No server needed. Proof generation for N=8 takes ~200ms locally.

### 2. Model weight commitment
`ModelCommitment` template uses `Poseidon` (ZK-friendly hash, 1 constraint per input). The commitment is stored in `CognitionVerifier.modelCommitment[agent]` and set at registration time. Any weight change requires re-registration and a new commitment — creating an audit trail.

### 3. Proof size vs. trusted setup
Current implementation uses **Groth16** — constant-size proofs (~192 bytes on-chain), but requires re-running setup if circuit changes.

To switch to **PlonK** (universal setup, no re-ceremony on logic changes):
```bash
# In zk-setup.ts, replace:
snarkjs groth16 setup  →  snarkjs plonk setup
snarkjs groth16 prove  →  snarkjs plonk prove
# And regenerate Verifier.sol with plonk template
```

## Scaling beyond N=8

Change the component instantiation in `relu.circom`:
```
component main {public [post, commitment]} = AgentCognitionProof(64, 64);
//                                                                 ^    ^
//                                                           neurons  weights
```

Then re-run `zk-setup.ts`. Increase `PTAU_POWER` if constraint count exceeds 2^current_power.
